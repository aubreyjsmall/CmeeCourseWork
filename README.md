### tabtocsv.sh
**Purpose:** Converts a tab-delimited file into a comma-delimited file.
**Usage** (from `CMEECourseWork/`):
`bash code/tabtocsv.sh <tab_delimited_file>`

**Behaviour:**
- Accepts exactly one readable input file and leaves it unchanged. 
- Paths containing spaces are supported.
- Writes the result to `CMEECoursework/results/<input-filename>.csv`
  (e.g. `tab-example.tsv` produces `../results/tab-example.tsv.csv`).
- Creates `CMEECoursework/results/` if it does not exist.
- Replaces the previous output on a rerun rather than appending.
- Preserves empty fields: consecutive tabs become consecutive commas.
- Leaves the input file unchanged.
- With no argument, prints a usage message to standard error and exits with status 2.
- With a missing or unreadable file, prints an error to standard error and exits with status 1

**Testing:** All tests used disposable files created in the sandbox directory, never the original data. Scripts were run from `code/`.

|---|---|---|---|

| Empty field kept | `cat results/tab-example.tsv.csv` | species,countoak,,12 | [species,countoak,,12] |
| Rerun | Run again, then `cat` the output | No duplicate rows |  [species,countoak,,12] |

**Limitations**
- Both scripts use simple character substitution with `tr`. They are not general parsers.
-  A comma inside a quoted CSV field is data, but these scripts would treat it as a separator.
- Quoted fields, embedded newlines, and escaping are not handled.
- In the space-separated output, a space inside a field cannot be told apart from a separator.

### Practical: validating tree-survey records

**Purpose:** Validate and clean the synthetic Silwood tree survey. Each record is either accepted (with its text normalised to a standard spelling) or rejected with the reason(s) it failed. The script also counts the accepted oak (Quercus) records by species.
**Usage** (from `CMEECourseWork/`):
```bash
python3 code/clean_silwood_trees.py     # run the cleaner
python3 code/test_silwood_trees.py      # run the tests
```
**Input:** `data/silwood_trees_raw.csv` (unchanged; the validation rules are in the metadata file in data/).

**Output:** (created in `results/`, replaced on each run, not committed):

## Assignment 3: Biological Computing in R 

### Calculate tree heights
**Purpose:** This function calculates the heights of trees given the distance of each tree from its base and the angle to its top, using  the trigonometric formula 

```height = distance * tan(angle in radians),   radians = degrees * pi / 180```

There are two routes. They share the same input checks and height calculation.

**Input:** `data/trees.csv` (supplied, unchanged), with columns `Species`, `Distance.m` and `Angle.degrees`.

**Input checks** (all run before anything is written, so invalid input never produces an output file):
1. The columns `Species`, `Distance.m` and `Angle.degrees` exist.
2. `Distance.m` and `Angle.degrees` are numeric (`is.numeric()`, so whole-number columns are accepted).
3. Both are finite: no `NA`, `NaN` or `Inf`.
4. `0 < Distance.m <= 100`.
5. `0 < Angle.degrees < 90`

#### Route 1: fixed script
```bash
Rscript code/TreeHeight.R
```

- Reads `data/trees.csv` (hard-wired) and previews its header and first rows.
- Applies the input checks, calculates all heights and builds a four-column table (`Species`, `Distance.m`, `Angle.degrees`, `height_m`).
- Writes `results/TreeHts.csv`, creating `results/` if needed and replacing any previous output.
- Prints `Script complete :)` when done.

#### Route 2: generalised script and wrapper

```bash
bash code/run_get_TreeHeight.sh                    # runs get_TreeHeight.R on data/trees.csv
Rscript code/get_TreeHeight.R <csv_file>           # the same script on any CSV
```

- `run_get_TreeHeight.sh` runs `Rscript code/get_TreeHeight.R data/trees.csv` and stops if the R script fails (`set -e`).
- `get_TreeHeight.R` accepts exactly one readable CSV path, applies the input checks and calculates the heights.
- The output name is built from the input's basename: `data/trees.csv` produces `results/trees_treeheights.csv`, and `sandbox/int_ok.csv` produces `results/int_ok_treeheights.csv`.
- Creates `results/` if needed and replaces any previous output.

**Testing:** all commands are run from the repository root. Create the small test inputs first (they live in the git-ignored `sandbox/`):

### Analyze Pound Hill species richnes

**Purpose:** Calculates species richness at the quadrat and plot levels from the Pound Hill abundance data, summarises mean plot-level richness for each cultivation treatment and draws a figure comparing the treatments.

**Usage** (from the repository root; `reshape2` and `ggplot2` must be installed):

```bash
Rscript code/pound_hill_analysis.R
```

**Files:**
- `code/pound_hill_analysis.R`: data processing, richness calculations and plotting.
- `data/pound_hill_data.csv`: input species abundance data (supplied, unchanged).
- `data/pound_hill_meta_data.csv`: input metadata (supplied, unchanged).
- `results/pound_hill_plot_richness.csv`: cultivation treatment, block, plot and mean species richness (one row per plot).
- `results/pound_hill_plot_richness.pdf`: figure of plot-level mean richness by cultivation treatment.

**Behaviour:**
- Checks that the input files and the required packages exist, and stops with an informative error if not.
- Replaces blank abundances with zero, transposes the matrix and reshapes it into long format.
- Converts cultivation, block, plot and quadrat identifiers to factors and counts to integers.
- Quadrat richness is the number of species with a count above zero; plot richness is the mean over the quadrats in each plot.
- Creates `results/` if needed, then saves the plot-level table as a CSV and the figure as a PDF.
- The figure shows one point per plot. Points are shifted slightly sideways (horizontal jitter only, with a fixed seed) so that equal or near-equal values do not hide each other. The richness values on the y axis are unchanged.
- Checks that the figure contains one point for each plot and that the plotted values equal the values in `PlotRichness`.

**Interpretation:** Mean plot-level richness is highest in the May treatment, but plots within each treatment vary widely and the treatments overlap. With four plots per treatment and no statistical test, the figure cannot show that cultivation timing caused the differences. Treatment assignment, block and site effects would also need to be known. (The same notes are at the end of the script.)
